## 1. The shape of it

- **Backend:** FastAPI monolith. `main.py` (4,150 lines) holds every route,
  the tool registry + executor, note-field validation, and the SSE turn
  generator. `inference.py` (2,100 lines) holds prompt assembly, the
  streaming tool loop, textual tool-call recovery, web search (Brave/SearXNG),
  fetch_url (via the search VM's Playwright "webtool"), screenshot_page
  (vision model via LM Studio), synthesis, titles, and notes synthesis.
- **Data:** per-user SQLite DB under `backend/data/users/<hash>/` with tables
  `turns` (tree via `parent_turn_id`), `recall_blocks`, `notes_index`
  (rebuildable cache over a markdown vault), `note_drafts`, `scratch`,
  `transcripts`, plus NWC ledger tables. Auth DB holds passkeys (Argon2id,
  transparent upgrade from legacy SHA-256) and device sessions.
- **Inference:** OpenAI-compatible calls to LM Studio; chat model + optional
  small `utility_model` for titles/synthesis; local fastembed (ONNX) for
  embeddings; brute-force cosine search in Python.
- **Voice:** server tier (streaming STT over WS with lexical phrase detection;
  TTS via Piper in-process or speaches sidecar) advertised via `/api/health`
  capabilities; frontend keeps an on-device fallback stack (Whisper
  worker, TF.js keyword spotting, Piper WASM).
- **Frontend:** one typed API seam (`src/api/collaborator.ts`), defensive
  adapters, `useConversation` owns the tree + active path + optimistic edits,
  tabs Conversations / Chats / Scratch / Mind, pushed screens for chat, map,
  references, web search, transcripts. Android shell is remote-URL Capacitor
  with a mic foreground service.
- **Docs drift:** AGENTS.md, DEPLOY.md, README, TESTING.md and the tracked
  `deploy.sh` all describe a Next.js standalone server. The frontend is Vite,
  and prod runs a hand-written `/srv/collaborator/deploy.sh`. `.config.yaml`
  is deprecated but still present locally (holds `voice_end_phrase`).
  `backend/fix_issues.py` is a dead one-off patch script committed to the repo.

### What is genuinely good (keep)

- **Tool-loop failure handling** — textual tool-call recovery across four
  dialects, the `_StreamGuard` that withholds blob-shaped output, unknown-tool
  correction, reasoning-budget-exhaustion detection, poisoned-history
  repairs (empty turns skipped, leading assistant turns dropped), honest
  "error vs empty vs never ran" outcome events, malformed-args salvage.
- **The frontmatter boundary** — model proposes structure only via typed tool
  params; `_normalize_note_fields` is the single validator for every entry
  path; the app alone writes YAML; index provably rebuildable from files.
- **KV-cache-aware prompt layout** — datetime/location/ambient hints go in a
  trailing system message so the static prefix stays cacheable.
- **Scratch isolation by construction** — separate table, content-addressed
  media, secret guard before any model contact, no content logging.
- **Voice tier design** — turn-ending is lexical inside the ASR stream, no VAD
  endpointing, bounded per-partial compute, capability advertisement.
- **NWC payments** — attempts parked before contacting the wallet, timed-out
  payments recovered via lookup, encryption scheme probed and persisted.
- **Auth** — Argon2id, device sessions (httpOnly cookie / X-Session), WS
  one-time tickets, lockout that never locks out existing sessions.
- **Frontend discipline** — one seam, adapters that guard every field,
  optimistic tree edits with server true-up (no rollback bookkeeping),
  the `docs/backend-sync.md` ledger, pure-logic vitest coverage, heavy ML
  chunks lazy-loaded and excluded from the SW precache, PWA update holds
  during calls.

## 2. Seams (where adding features hurts)

1. **Adding one tool touches ~6 places in 2 repos.** Schema in
   `_build_tools` (main.py ~563–900), execution in its ~390-line if-chain
   (~902–1289), description in `tools-spec.md` + `DEFAULT_TOOL_DESCRIPTIONS`
   (~422), status label `_tool_status_label` and outcome `_tool_outcome_event`
   in inference.py (~1526–1629), `_POSITIONAL_ARG_KEY` (~1634), and
   `toolIcon()` in the frontend. → A `tools/` package with one module per
   tool exposing `spec()`, `execute(ctx, args)`, `status_label()`,
   `outcome()`; `_build_tools` becomes a loop over enabled modules. This is
   the prerequisite for attachment tools.
2. **Note-field validation + frontmatter serialization** (main.py ~1380–1707)
   live in the routes file. Belong in a `notes_fields.py` next to
   `notes_index.py`.
3. **Two inference paths** (`stream_llm_tokens` vs `generate_with_tools`)
   duplicate SSE parsing and the reasoning-exhaustion fallback. Dead code:
   `call_llm_non_streaming`, `chat_with_retry`, `get_cached_models`,
   `call_llm`, `get_context_for_turn`, `get_latest_turn_id`,
   `update_turn_committed`, the `conversations` table, `fix_issues.py`.
4. **The turn row is a grab-bag.** tags / recall_sources / tool_activity /
   location are JSON in TEXT columns; embedding BLOB inline. `get_turn_tree`
   loads every committed turn's full content + recall + tool activity on
   every `GET /api/tree`.
5. **Config caching inconsistency.** Base system prompt is folded into the
   config singleton at startup; every other prompt layer is read fresh per
   turn. Three config sources (config.yaml, deprecated .config.yaml,
   app_settings.json) plus env.
6. **`main.py` route groups** (candidate routers): chat/turns, tree/export,
   notes + drafts + events, scratch, transcripts, models/prompts, auth,
   voice (transcribe/WS/TTS).

## 3. Bugs and risks (file:line, most important first)

- **SQLite: no WAL, no `busy_timeout`, no foreign-key pragma** (db.py has no
  PRAGMA anywhere; `sqlite3.connect` per request throughout main.py).
  Background threads (transcribe jobs in agent_tools.py:418, title
  generation, voice preload) write concurrently → "database is locked" is a
  matter of time. Fix: one connection helper setting `journal_mode=WAL`,
  `busy_timeout=5000`, `synchronous=NORMAL`, `foreign_keys=ON`.
- **Blocking work on the event loop.** These `async def` handlers call
  `requests` or run fastembed synchronously on the loop:
  `manual_web_search` (main.py:2890), `list_models` (3268),
  `search_vault_notes` (2562, `get_embedding`), `reindex_notes` (2513),
  `reindex_embeddings` (3596), `approve_draft` (2417, `index_note_file`
  embeds), `_find_duplicate_notes` callers in `synthesize_tree_notes`
  (2301). Stalls every other request incl. the WS audio stream. Fix: make
  them plain `def` (Starlette threadpools sync handlers) or `asyncio.to_thread`.
- **Post-reply work delays the visible end of the reply.** In
  `_stream_turn_response`: both turns embedded before the `done` event
  (main.py:1992–1999); `_maybe_update_title` runs after `done` but inside
  the generator (2035), holding the HTTP response and a threadpool slot for
  up to `titles.timeout` (30 s). → background job.
- **Recall search is O(N) Python with N root-walks.** `search_similar_turns`
  (db.py:708–765) computes cosine per row in a Python loop and calls
  `get_root_id` (one query per parent hop) for EVERY scored row, not just
  top-k. Same in `search_keyword_turns` (768–811). Fix: cache a numpy matrix
  of embeddings per DB (invalidate on write), one matmul, then resolve
  branch roots only for the top-k via the recursive CTE already used in
  `count_tree_turns` (490).
- **Full scans with per-row JSON parsing:** `get_backlinks`
  (notes_index.py:349), `list_events` (513), `search_notes_keyword` (543),
  `search_notes_semantic` (395), `graph_neighborhood` (432),
  `search_transcripts` (db.py:1187, loads all transcript text),
  `get_note_by_title` (341: `lower(title) = lower(?)`, no index). Ambient
  hints (`_ambient_note_hints`, main.py:1800) run a vault embedding search on
  every tools turn.
- **`POST /api/transcribe` (main.py:3702) ignores sessions** — checks only
  `X-Passkey`, so cookie-authenticated browser clients get 403. Frontend now
  dictates over the WS, so likely dead, but broken.
- **SSRF guard TOCTOU** — `_host_is_private` (inference.py:1235) resolves
  once; `requests.get` (1426) resolves again and follows redirects
  unchecked. Low risk for a private single-user box. Fix:
  `allow_redirects=False` + per-hop check on the direct path.
- **Lockout is global** (auth.py:165–202) — one remote attacker can block new
  logins for everyone (sessions survive, by design). Key it per source IP.
- **`_last_seen_cache`** (auth.py:215) grows unbounded (trivial).
  **`_ws_tickets`** in-memory (fine, 30 s TTL).
- **`StreamSession.audio`** (voice.py:344) holds full session PCM
  (32 KB/s → ~115 MB/hour); fine for calls, note for very long sessions.
- **`delete_turn`** doesn't clear dangling `recall_sources` /
  `note_drafts.source_turns` references (acknowledged harmless).
- **`transcribe_audio`** reads the whole upload into memory and trusts the
  Content-Length header for the size check.
- **Frontend `useHealth`** polls `/api/health` AND `/api/models` every 15 s
  per open tab; `/api/models` makes the backend hit LM Studio twice
  (`/v1/models` + `/api/v0/models`) each time.
- **Frontend per-token full re-render** — `onToken` → `setStreaming` per
  chunk (useConversation.ts:230); ChatView re-parses the entire growing reply
  through react-markdown on every token (ChatView.tsx:534).
- **Frontend tree refetch after every mutation** — `api.getTree()` after
  every send/branch (useConversation.ts:244), every `confirmMutation`, and
  on call close. Cost grows with the whole corpus per message.
- **Server TTS awaits the full sentence blob** (`res.blob()`,
  collaborator.ts:677) so the streaming WAV endpoint buys nothing; the
  PCM + AudioContext path is parked in the ledger.
- **Deprecation:** `starlette.testclient` with `httpx` warns; the next
  Starlette bump will break the test client unless `httpx2` is pinned.
- **Lower-priority notes:** `PUT /api/model` is per-install and any session
  can change it (acknowledged); `generate_with_tools` executes tool calls
  sequentially even when the model emits several independent ones in a
  round; `_load_tool_descriptions` re-reads tools-spec.md and rebuilds ~20
  schema dicts every turn (cheap, but cacheable by mtime).

## 4. Optimization plan (backend + frontend)

Suggested order; every step is covered by the existing 237 tests.

1. **SQLite pragmas + connection helper + indexes.** Partial index on
   `turns(committed) WHERE embedding IS NOT NULL`; `transcripts(url)`;
   `note_drafts(status, run_id)`; `notes_index(lower(title))` (expression
   index) or a stored `title_lower` column.
2. **Vectorized recall** (matrix cache per user DB, top-k root resolution).
   Same treatment for `search_notes_semantic`.
3. **Off-loop handlers** — `async def` → `def` for every handler that calls
   `requests`/fastembed (list above).
4. **A small background job runner** (thread pool + status table) replacing
   the three ad-hoc thread patterns (transcribe worker, voice preload,
   in-generator title/embedding work). Post-`done` embedding + titles move
   here. This is also what attachments ingestion will use.
5. **Tools registry refactor** (`tools/` package, one module per tool).
6. **Parallel tool execution** for independent calls within a round.
7. **`/api/tree` diet** — `?root=` filter, `If-None-Match`/ETag, omit
   `recall_sources`/`tool_activity` until requested (or a skeleton endpoint +
   per-root content). Frontend reloads only the affected root.
8. **Split `main.py`** into routers; move note-field code out.
9. **Delete dead code**; fix docs (Next.js references, README auth default,
   TESTING.md); drop `.config.yaml`.
10. **Frontend:** batch tokens on `requestAnimationFrame`; memoize completed
    paragraphs so only the streaming tail re-parses markdown; poll
    `/api/models` at 60 s or on focus instead of every 15 s; scope tree
    refetches; PCM + AudioContext gapless TTS scheduling; consider
    `startTransition` for tree applies.

## 5. Adding documents, OCR, images, and voice memos

**Key insight:** the scaffolding already exists inside Scratch. Already
present: content-addressed per-user media store (`scratch.save_media`),
authenticated media endpoint (`GET /api/scratch/{id}/media`), frontend blob
cache for authed images (`mediaCache.ts`), `voice.transcribe_batch` (routes
to speaches or local Whisper), a vision-model call pattern in
`screenshot_page` (inference.py:1318 — sends `image_url` content parts to LM
Studio), `tools.screenshot.vision_model` already configured (qwen2.5-vl),
`/api/models` already reporting which loaded models are `vlm`, and the
`act` pipeline with `unsupported` placeholders for image/video. The Composer
"+" button is a disabled "coming soon".

**Plan:** promote "media on a scratch item" into a first-class
**attachment** resource that turns, scratch items, and notes can reference.

1. **Data model** (per-user DB):
   - `attachments`: id, sha256, mime, size, original_name, kind
     (image | document | audio | video | file), path, created_at,
     extracted_text, extraction_method (pdftext | ocr | stt | vision),
     extraction_status (pending | done | error), language, page_count /
     duration_s, caption (images), embedding BLOB.
   - `attachment_chunks`: attachment_id, seq, text, embedding — shares the
     fastembed vector space with turns and notes so one search covers all.
   - `turn_attachments`: turn_id, attachment_id, position.
   - Reuse the scratch media directory (rename `scratch-media` → `media`);
     `scratch.media_hash` can become a FK to `attachments.sha256`.
2. **Ingest pipeline** (`ingest.py`, runs in the job runner): one entry
   `ingest(db_path, bytes, mime, name) -> attachment`, dispatch on kind:
   - **PDF / text / docx:** PyMuPDF text extraction; pages with no text
     layer → render to PNG → OCR.
   - **Images:** strip EXIF, thumbnail, OCR pass, vision caption via the
     configured vision model; `extracted_text` = caption + OCR text.
   - **Audio (voice memo):** ffmpeg normalize → `voice.transcribe_batch`,
     background for long files exactly like `transcribe_video`.
   - **Video:** audio track → same as audio (keyframes + vision later).
   - Chunk + embed with `embed_texts`.
   - OCR engine recommendation: **rapidocr-onnxruntime** (pure pip, ONNX
     only — consistent with fastembed / faster-whisper's no-PyTorch stance).
     Tesseract (`pytesseract` + system package) as fallback if quality
     disappoints; vision model as last resort.
3. **Attachments on a turn:** `POST /api/attachments` (multipart) → id(s);
   `UserMessage.attachments: List[int]` (and `BranchRequest`). In
   `_build_messages`: when the active model is a vlm, the attaching user
   message becomes a content-part list with `image_url` entries (currently
   `content` is always a string — this is the one inference.py change).
   Otherwise, and for documents, inject bounded extracted text with a note
   that `read_attachment` can page the rest. Later history turns carry only
   caption/text, never the image bytes again (KV cache + token budget).
   Persist `turn_attachments` so the tree renders thumbnails.
4. **Tools** (after the registry refactor): `list_attachments`,
   `search_attachments(query, kind?)` over chunks, `read_attachment(id,
   chunk?)` paged like fetch_url, `describe_image(id, question?)` reusing
   the screenshot vision call. Fold the transcript redesign in: a YouTube
   transcript is an audio attachment with a source URL, so
   `list_transcripts` / `read_transcript` become the same tools.
5. **Recall / notes integration:** `recall_semantic` gains attachment chunks
   as a source type (`source: attachment` in results) or a separate tool;
   ambient hints include attachment titles; `propose_note` can cite
   `source_attachments` (a deliberate whitelist addition per NOTES-FORMAT).
6. **Voice memos** need the least new code: Scratch already records raw
   audio and transcribes on hold-send. Gaps: transcribe-on-capture as a
   background job, store transcript as extracted text for recall, playback
   with progress, and a Composer path that records a memo → audio attachment
   → transcript becomes the message while the audio is kept.
7. **Frontend:** enable the Composer "+" for file + camera; upload first
   with progress, send with ids; chips with thumbnails above the composer;
   render thumbnails / document chips / audio players in `TreeBubble` via
   the existing blob cache; scratch photo/voice cards get "Describe" / "OCR"
   actions instead of `unsupported`; an Attachments lens under Mind.

**Build order:** foundation pass (§4 items 1–5) → documents (pure text,
exercises the whole path) → images with OCR + vision → voice memos + transcript
unification → attachment tools + recall integration + frontend surfaces.

**New dependencies:** PyMuPDF, rapidocr-onnxruntime, Pillow. No new model
host (vision runs in LM Studio). ffmpeg already required on prod.
